# 路由切换与依赖审计修复设计

## 目标

消除异步路由切换时主内容短暂空白的问题，并恢复 npm 依赖审计通过状态。

## 范围

- 保留现有页面淡入淡出效果，但不再使用会先卸载当前页面的 `out-in` 切换模式。
- 将 `sharp` 升级到审计要求的安全版本，并同步锁文件。
- 仅更新审计报告中可由依赖升级消除的依赖；不修改状态接口、页面结构或视觉设计。

## 方案

`App.vue` 的路由过渡改为默认的同步过渡。新旧页面在过渡期间可短暂重叠，避免懒加载组件解析期间留下空的主内容区；现有 180ms 的透明度动画和减少动效媒体查询保持不变。

依赖升级使用 npm 的锁定版本更新。升级后执行英雄图优化脚本，因为它是 `sharp` 的唯一直接调用方；只有脚本输出与构建成功时才接受升级结果。

## 验证

- 为路由壳层补充结构测试，锁定不使用 `out-in`。
- 先运行该测试并确认当前实现失败，再做最小实现。
- 运行 `npm audit`、`npm test`、`npm run typecheck`、`npm run build`。
- 在浏览器中验证首页到下载页切换不再出现主内容空档，并复查下载确认流程。

## 非目标

- 不为状态接口添加重试、缓存或调整超时；本次审查确认其最终可用，慢响应属于独立的服务体验议题。
- 不引入新的依赖、加载骨架或路由预取策略。
