# 下载客户端状态提示设计

## 背景与目标

下载页目前会直接打开安装确认对话框，但不会读取对应平台的客户端状态。用户可能在本地化客户端尚未同步、状态数据缺失或状态服务不可用时继续下载，却得不到必要提醒。

本次改动在不阻塞下载的前提下，将现有状态服务接入下载确认流程。状态提示只提供风险信息，不改变下载入口可用性，也不引入新的状态判定规则。

## 范围

### 包含

- 进入下载页后读取一次客户端状态。
- Android、iOS、Windows 和 macOS 下载平台分别读取同名状态资源。
- 在现有下载确认对话框内展示检查中或异常提示。
- 请求失败、超时、状态缺失和版本未同步时允许继续下载。
- 页面卸载时取消尚未完成的状态请求。
- 使用现有 Material 2 语义颜色和 Vuetify 组件。

### 不包含

- 不阻止、禁用或延迟下载操作。
- 不在平台卡片上持续展示状态。
- 不修改状态页现有布局或文案。
- 不新增状态重试按钮。
- 不把状态更新时间纳入异常判定；数据过期阈值需要独立确认。

## 数据与职责

### 平台映射

`PlatformLink` 增加明确的 `statusKey`，避免在页面中根据名称或 URL 推断：

| 下载平台 | 状态资源 |
| --- | --- |
| Android 平台 | `android` |
| iOS 平台 | `ios` |
| Windows 平台 | `windows` |
| macOS 平台 | `macos` |

### 状态来源

下载页复用 `src/utils/status.ts`：

- `fetchStatus` 负责请求、超时和响应结构检查。
- `mapStatusResources` 负责把版本信息转换为统一状态。
- 下载页只负责请求生命周期、选中平台映射和提示文案。

这样状态页与下载页共享“已同步、未同步、未获取”的判定，不复制接口解析逻辑。

## 交互流程

1. 下载页挂载后立即调用 `fetchStatus`。
2. 请求期间记录为“检查中”；页面卸载时通过 `AbortController` 取消请求。
3. 请求成功后调用 `mapStatusResources` 保存各平台状态；请求失败则保存失败状态。主动取消不显示错误。
4. 用户选择下载版本时，现有安装确认对话框立即打开。
5. 对话框根据所选平台展示：
   - 检查中：普通状态提示“正在检查客户端状态……”。
   - 已同步：不显示额外提示。
   - 未同步：warning 提示本地化客户端可能尚未同步到最新官方版本。
   - 未获取：warning 提示暂时未取得该客户端状态。
   - 请求失败或超时：warning 提示暂时无法确认该客户端状态。
6. “继续下载”在所有状态下保持可用，原有下载追踪行为不变。

## 视觉与可访问性

- 提示放在下载确认对话框的说明文字之后、操作按钮之前，与下载决策保持上下文关联。
- 检查中提示使用现有 `info` 语义；异常使用现有 `warning` 语义。
- 不使用 `error` 红色，因为这些状态是风险提示而不是阻止下载的错误。
- 异常提示使用 `role="alert"`，确保异步返回的异常能被辅助技术播报。
- 检查中提示使用 `role="status"`，避免打断式播报。
- 提示包含图标和文字，不只依赖颜色传达状态。

## 错误处理

- HTTP 错误、无效响应、网络错误和 `StatusRequestTimeoutError` 统一显示“暂时无法确认”提示。
- 页面卸载导致的 `AbortError` 不更新界面、不显示提示。
- 接口返回对象但缺少所选平台或版本字段时，显示“暂时未取得状态”提示。
- 状态请求不会影响对话框打开、下载链接或分析事件。

## 测试与验收

自动化测试覆盖：

- 四个平台都声明正确的 `statusKey`。
- 页面挂载时发起状态请求，卸载时取消请求。
- 已同步状态不显示额外提示。
- 检查中显示普通状态提示。
- 版本未同步、状态缺失和请求失败分别显示对应警告。
- 异常状态下“继续下载”仍可点击，原有下载追踪仍执行。

手动浏览器验证覆盖：

- 桌面与移动端对话框布局无溢出。
- 异常提示层级清晰，但不压过“继续下载”主操作。
- 请求完成后的动态提示正确出现，控制台无错误。
